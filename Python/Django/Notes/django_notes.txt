DJANGO FULL NOTES
=================

1. WHAT IS DJANGO
-----------------
Django is a Python web framework used to build web applications quickly and securely.

Django follows MVT architecture:

M = Model
V = View
T = Template


2. DJANGO PROJECT VS APP
------------------------
PROJECT:
The complete Django website/application.

APP:
A feature/module inside the project.

Example:

myproject
    |
    |-- users
    |-- products
    |-- orders
    |-- payments


3. VIRTUAL ENVIRONMENT
----------------------

WINDOWS:
py -m venv venv

MAC:
python3 -m venv venv

WHY USE IT:
Creates an isolated Python environment for the project.
It prevents packages from different projects from conflicting.


4. ACTIVATE VIRTUAL ENVIRONMENT
-------------------------------

WINDOWS CMD:
venv\Scripts\activate

WINDOWS POWERSHELL:
.\venv\Scripts\Activate.ps1

MAC:
source venv/bin/activate

After activation:

(venv) hasib@MacBook Django %

DEACTIVATE:
deactivate


5. INSTALL DJANGO
-----------------

WINDOWS + MAC:
pip install django

SAFER:
python -m pip install django

CHECK DJANGO VERSION:
python -m django --version

WHY:
Installs Django inside the active virtual environment.

------------------------

WINDOWS:

MAC:
python3 -m django startproject myproject

django-admin startproject myproject

WHY:
Creates the basic Django project files and configuration.

11. ADD APP TO settings.py
--------------------------

Open:

myproject/settings.py

Find:

INSTALLED_APPS = [
    ...
]

Add:

INSTALLED_APPS = [
    ...
    "myapp",
]

WHY:
Tells Django that myapp is part of the project.


12. PROJECT urls.py
-------------------

File:

myproject/urls.py

Example:

from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path("admin/", admin.site.urls),
    path("", include("myapp.urls")),
]

WHY:
Project urls.py controls the main URL routing and connects app URLs.


13. APP urls.py
---------------

Django does not automatically create urls.py inside an app.

Create:

myapp/urls.py

Code:

from django.urls import path
from .views import index

urlpatterns = [
    path("", index, name="index"),
]

WHY:
Defines URLs belonging to the app.


14. VIEWS
---------

File:

myapp/views.py

Code:

from django.shortcuts import render

def index(request):
    return render(request, "index.html")

WHY:
A view receives a request, performs logic, and returns a response.

17. PASS DATA FROM VIEW TO TEMPLATE
-----------------------------------

views.py:

from django.shortcuts import render

def index(request):
    name = "Hasib"
    age = 22

    return render(
        request,
        "index.html",
        {
            "name": name,
            "age": age
        }
    )

index.html:

<h1>Hello {{ name }}</h1>
<p>Age: {{ age }}</p>

{{ variable }}
is used to display data in a template.


18. TEMPLATE IF
---------------

{% endif %}


19. TEMPLATE FOR LOOP
---------------------

views.py:

def index(request):
    students = ["Hasib", "Ali", "Ahmed"]

    return render(
        request,
        "index.html",
        {"students": students}
    )

index.html:

{% for student in students %}
    <p>{{ student }}</p>
{% endfor %}

21. MODELS
----------

Models define database tables using Python classes.

models.py:

from django.db import models

class Student(models.Model):
    name = models.CharField(max_length=100)
    email = models.EmailField()
    age = models.IntegerField()
    phone = models.CharField(max_length=15)

Django automatically creates an id field if no primary key is specified.

DATABASE TABLE:

Student
----------------
id
name
email
age
phone


22. COMMON MODEL FIELDS
-----------------------

DECIMAL:
price = models.DecimalField(
    max_digits=10,
    decimal_places=2

BOOLEAN:
is_active = models.BooleanField(default=True)

EMAIL:

DATE:

DATETIME:
created_at = models.DateTimeField(auto_now_add=True)

-------------

Student object (1)

30. ORM
-------

ORM = Object Relational Mapping

Django ORM allows you to work with database data using Python instead of writing SQL manually.

SQL:

SELECT * FROM student;

Django ORM:

Student.objects.all()


31. CREATE DATA
---------------

METHOD 1:

s = Student(
    name="Hasib",
    email="hasib@gmail.com",
    age=22,
    phone="9876543210"
)

s.save()

WHY:
Student() creates the Python object.
save() stores it in the database.


METHOD 2:

Student.objects.create(
    name="Hasib",
    email="hasib@gmail.com",
    age=22,
    phone="9876543210"
)

WHY:
Creates and saves the database record in one operation.


32. READ DATA
-------------

GET ALL:

Student.objects.all()

Example:

students = Student.objects.all()

for student in students:
    print(student.name)


GET ONE:

student = Student.objects.get(id=1)

WHY:
get() is normally used when exactly one object is expected.


FILTER:

students = Student.objects.filter(age=22)

WHY:
filter() returns all records matching the condition.


33. ORM LOOKUPS
---------------

GREATER THAN:
Student.objects.filter(age__gt=18)

GREATER THAN OR EQUAL:
Student.objects.filter(age__gte=18)

LESS THAN:
Student.objects.filter(age__lt=30)

LESS THAN OR EQUAL:
Student.objects.filter(age__lte=30)

CONTAINS:
Student.objects.filter(name__contains="Has")

CASE-INSENSITIVE CONTAINS:
Student.objects.filter(name__icontains="has")


34. UPDATE DATA
---------------

s = Student.objects.get(id=1)

s.name = "Ali"
s.age = 25

s.save()

WHY:
get() gets the object.
Values are changed.
save() stores the changes.


DIRECT UPDATE:

Student.objects.filter(id=1).update(
    name="Ali",
    age=25
)


35. DELETE DATA
---------------

s = Student.objects.get(id=1)

s.delete()

OR:

Student.objects.filter(age=20).delete()

WHY:
delete() removes records from the database.

41. RELATIONSHIPS
-----------------

Django supports:

1. One-to-One
2. One-to-Many
3. Many-to-Many


42. FOREIGNKEY - ONE TO MANY
----------------------------

class Department(models.Model):
    name = models.CharField(max_length=100)


class Student(models.Model):
    name = models.CharField(max_length=100)

    department = models.ForeignKey(
        Department,
        on_delete=models.CASCADE
    )

Meaning:

One Department
      |
      +-- Student
      +-- Student
      +-- Student


43. on_delete
-------------

CASCADE:

on_delete=models.CASCADE

If the parent object is deleted, related objects are deleted.

Other common options:

models.PROTECT
models.SET_NULL
models.SET_DEFAULT


44. ONE-TO-ONE
-------------

class UserProfile(models.Model):

    user = models.OneToOneField(
        User,
        on_delete=models.CASCADE
    )

Meaning:

One User -> One Profile


45. MANY-TO-MANY
---------------

class Student(models.Model):
    name = models.CharField(max_length=100)


class Course(models.Model):
    name = models.CharField(max_length=100)

    students = models.ManyToManyField(Student)

Meaning:

Student A -> Python
Student A -> Django

Student B -> Python
Student B -> Java


46. FORMS
---------

Django forms handle user input.

forms.py:

from django import forms

class StudentForm(forms.Form):
    name = forms.CharField(max_length=100)
    email = forms.EmailField()
    age = forms.IntegerField()


47. MODELFORM
-------------

forms.py:

from django import forms
from .models import Student

class StudentForm(forms.ModelForm):

    class Meta:
        model = Student
        fields = "__all__"

WHY:
ModelForm automatically creates form fields based on the model.


48. GET AND POST
----------------

GET:
Used mainly to retrieve data.

request.GET


POST:
Used mainly to submit data.

request.POST

Example:

def student(request):

    if request.method == "POST":
        name = request.POST.get("name")

    return render(request, "student.html")


49. CSRF
--------

Django protects POST forms using CSRF protection.

HTML:

<form method="POST">

    {% csrf_token %}

    <input type="text" name="name">

    <button type="submit">
        Save
    </button>

</form>

WHY:
Protects forms from Cross-Site Request Forgery attacks.


50. TEMPLATE INHERITANCE
------------------------

base.html:

<!DOCTYPE html>
<html>
<head>
    <title>{% block title %}{% endblock %}</title>
</head>

<body>

    {% block content %}
    {% endblock %}

</body>
</html>


Another page:

{% extends "base.html" %}

{% block title %}
Home
{% endblock %}

{% block content %}

<h1>Welcome</h1>

{% endblock %}

WHY:
Avoids repeating common HTML code.


51. NAMED URLS
--------------

urls.py:

path("student/", student, name="student")

Template:

<a href="{% url 'student' %}">
    Student
</a>

WHY:
Avoids hardcoding URLs and makes URL changes easier.


52. REDIRECT
------------

from django.shortcuts import redirect

return redirect("index")

WHY:
Sends the browser to another URL.

RENDER:
return render(request, "index.html")

RENDER:
Returns an HTML template.

REDIRECT:
Sends the browser to another URL.

When your virtual environment is activated and you see:

(venv)

use:

python manage.py runserver

Do NOT use:

/usr/local/bin/python3 manage.py runserver

The /usr/local/bin/python3 command can use a different Python installation where Django is not installed.
